# hdc shell 与本机 Oh My Zsh 的体验差异

本文保留差异检视、历史变更和验证证据；当前规格与开发约束统一见 [AGENTS.md](../AGENTS.md)。版本记录中的旧行为不代表当前要求。

本轮只处理增强 `hdc shell`。它是 PowerShell 本地编辑器连接 OpenHarmony 设备端 sh 的会话，命令、路径和包名以设备为准，不引入主机的 Git 或 zsh 补全。普通 PowerShell 的编辑配置保持原样。

参照本机实际配置：`~/.zshrc` 中的 `zsh-autosuggestions`、`zsh-completions`、`zsh-syntax-highlighting`，以及 Oh My Zsh 的 `lib/key-bindings.zsh`、`lib/completion.zsh`。提示符按用户要求显示 `SN 文件夹名称 ->`,箭头以绿/红表示上一条命令成功/失败;历史继续按远端目录保存、跨设备共用。

| 能力 | 检视出的差异 | 本轮处理 |
|---|---|---|
| 命令发现 | 只扫描四个固定目录，可能漏掉设备 PATH 中的工具 | 从设备 `$PATH` 扫描实际可执行文件，含可执行符号链接；缓存五分钟 |
| 主机隔离 | 为设备命令创建主机同名空函数；其他预测插件可能提供主机命令 | 删除空函数代理；远端只使用目录历史预测；补全不查询主机命令或主机文件 |
| 路径解析 | 按空格拆分，带空格、引号的路径补全失败 | 按 sh 引号、反斜杠与运算符识别词；插入时保留 zsh 的反斜杠或单双引号方式,目录补全不擅自关闭引号 |
| 行中补全 | 仅处理光标左边，可能残留原词后半段 | 替换整个当前词，保留并匹配光标后的原词后缀,保留后续参数、管道和命令 |
| 复合命令 | 只识别最后一个管道 | 支持 `\|`、`\|\|`、`&&`、`;`、重定向及常见条件命令位置；引号内的符号不作为分隔符 |
| 目录与可执行路径 | `cd` 也列出普通文件；首词带 `/` 无法补全命令路径 | `cd`、`rmdir` 只列目录；命令位置的 `./`、绝对路径只列可执行文件和目录 |
| 特殊路径 | 缺少隐藏文件与家目录处理 | 支持 `./`、`../`、`~/`；输入点前缀才显示隐藏项；保留设备文件名大小写 |
| 常用选项 | 所有参数位置都只查文件 | 增加 `ls`、`cat`、`grep`、`find`、`ps` 等常见选项，以及 `bm`、`aa`、`param` 的常用子命令；`bm … -n`、`aa … -b` 补设备包名 |
| Tab | 第一次 Tab 直接选中候选 | 严格按本机 zsh 的公共前缀扩展、列候选、菜单选择顺序处理;菜单支持方向键、Tab / Shift+Tab;Enter 确认、下一次 Enter 执行;Esc 保留候选,Ctrl+G / Ctrl+C 撤回菜单选择 |
| 编辑模式 | 继承主机 Windows 编辑模式 | 设备会话临时使用 Emacs；Ctrl+A/E、Ctrl+R/S、Ctrl+U/K/W、Ctrl+Y 等基础操作可用 |
| 接受建议 | Ctrl+F 在行中也接受整条;缺少 Ctrl+E;逐词移动与接受的分隔符边界不同 | → / Ctrl+F 在行中移动一字、行尾接受整条；End / Ctrl+E 先到行尾，再接受整条；Ctrl+→ / Alt+F 按本机 zsh 边界逐词接受,包含其分隔空格或 `/` |
| 历史规则 | 历史大小写不敏感；可能从主机历史文件合并命令 | 目录历史独立读写，最近前缀匹配、区分大小写；↑↓前缀搜索、Ctrl+R 反向搜索；空格开头不记历史；禁用主机历史文件同步 |
| 输入配色 | 参数、数字与运算符过度着色；预测采用自定义蓝灰 | 命令绿、引号字符串黄、变量青、参数及普通文字默认色、预测 ANSI 灰色；仍由 PSReadLine 渲染 |
| 路径强调 | 1.1.3 只增加下划线,路径仍是白色 | 1.1.4 对已存在的设备路径和行尾可匹配路径的前缀显示亮青色与下划线;引号片段沿用黄色覆盖规则。路径范围与本机 zsh 对齐,颜色按用户要求增强;不修改缓冲区、光标或按键 |
| 连接与提示符 | 首次进入查询多个值,且提示符没有设备识别和成功/失败标记 | 1.1.6 移除版本查询和连接说明;命令扫描、HOME 查询延迟到需要时。每行显示 `SN 文件夹名称 ->`,只显示末级目录,箭头成功绿/失败红,提示符使用本地追踪值 |
| 命令输出与中断 | 等命令结束后才显示,`hilog` 等持续命令看起来卡住 | 1.1.5 默认所有命令实时输出,只有需本地排版的简单 `ls` 缓冲;按 Ctrl+C 中断本次 RPC 的远端进程组,返回设备提示符并设置状态 130;未知命令及管道不需要额外规则 |
| 交互执行通道 | 每条命令新建 hdc 进程和连接,交互使用约 200 ms/命令 | 1.2.0 在 Unix 主机复用一条持久 `hdc shell`;每条命令在独立子 shell 中执行,交互约 20–60 ms/命令;Windows、PTY 失败或命令过长时回退逐命令 RPC |
| stdin 与挂起 | 只输入 `cat` 等读取 stdin 的命令会一直等待,整个会话看起来卡死 | 1.1.7 远端命令的 stdin 指向 `/dev/null`,`cat`、`sort`、`head`、`read` 等立即得到 EOF 并按自身状态返回;管道、重定向和文件参数不受影响;需要交互输入的程序仍用 `--raw` |
| `ls` 输出 | 已有类型着色与多列排版 | 保留目录、可执行文件、符号链接及扩展名着色，不改变现有输出策略 |
| `ls` 参数与标记 | `-S` 与 `-s` 不区分大小写;显式 `-p` 会泄漏内部 `-F` 的可执行/链接标记;非长格式 `-h` 的 total 行被当作文件名参与分栏 | 1.1.7 标志判断区分大小写:`-S` 正常本地分栏,`-s`、`-m`、`-i`、`-Q` 和 `-h` 保持设备输出;显式 `-F` 保留全部标记,显式 `-p` 只保留 `/` |
| 取消与退出 | 空行 Ctrl+C 也退出设备会话 | Ctrl+C 在菜单内撤回选择,普通输入时取消当前行并留在设备；Ctrl+D 空行退出、非空删除字符；`exit` / `logout` 退出 |
| 目录和状态 | 每次 RPC 重建 shell，`cd -`、下一行 `$?` 不正确 | 本地追踪并传递 `cwd`、`OLDPWD` 和上一条退出码；尾部注释不会再吞掉内部状态标记 |
| 入口 | `hdc -t SERIAL shell` 绕过增强会话 | 与 `hdc shell` 一样进入增强会话；两种入口都支持 `--raw` |
| 退出恢复 | 只恢复三个按键；自定义快捷键无法恢复 | 保存并恢复编辑模式、完整按键表、配色、预测、历史选项、提示符和 TabExpansion2；异常退出也执行清理 |

## 逐键一致的验收

同一组候选、相同历史和初始目录下,向本机真实 Oh My Zsh 与增强 hdc shell 重放完全相同的按键。不通过额外探测按键读取状态,而是从编辑器旁路记录,逐步比较完整输入缓冲区、光标偏移和实际提交的命令文本。空格、引号、反斜杠和回车提交次数均参与比较。覆盖 35 组流程、111 个缓冲区/光标检查点,包括行中补全与后续参数。

```sh
python3 tests/HdcShell.Parity.py
```

例如 `cat plain\ f<Tab>NEXT<Enter>` 两侧均提交 `cat plain\ file NEXT`;用户无需再补空格。`cd loca<Tab><Enter>` 两侧均提交 `cd local`,临时 `/` 的处理也相同。菜单内的回车次数依据本机 zsh 实测,不是额外添加的确认步骤。

此对照测试用临时文件树与本地 hdc 测试适配器控制候选完全一致;真实设备链路另由 Integration 测试验证。覆盖的流程通过不代表所有 zsh 功能都已完全实现,未覆盖的能力列在下方。

## 仍未达到完全一致的能力

这些差异没有被基本配色或候选列表替代掉：

- **未知命令即时红色、完整 sh 语法高亮**：PSReadLine 使用 PowerShell 的词法解析与固定类别配色,未知命令仍可能呈绿色,部分 sh 结构的颜色和多行接受行为仍与 zsh 不同。原生控制台接口代理为设备路径叠加亮青色与下划线,没有替换整个 sh 语法解析器。路径强调不执行命令替换或任意变量展开;支持字面路径、引号、转义空格、`~` 与设备 `$HOME` / `$PWD` / `$OLDPWD`。设备目录列表与补全共用 10 秒缓存,行内强调结果按输入行缓存,控制台样式在每条新输入行重置。
- **完整 zsh 补全规则**：本轮加入的是设备常见命令的基本规则，不是 zsh-completions 全库。不同系统版本的 `bm`、`aa`、`hilog` 选项可能不同；尚未覆盖所有参数取值、部分词/子串匹配、任意变量及命令替换的展开。
- **持久 shell 状态**：Unix 主机会话复用一条持久 `hdc shell` 通道，但每条命令仍在独立子 shell 中执行。跨命令保留目录、上一个目录和退出码；`export`、普通变量、别名、函数、umask、shell 选项、作业状态不跨命令保留。PTY 不可用或命令过长时回退到逐命令 RPC。多行脚本、复杂命令替换不保证与原生 sh 一致。
- **PTY、交互式输入与作业控制**：持续日志和大输出已通过默认实时通道处理,不再要求为了 `hilog` 切换 `--raw`。持久通道只作为 hdc 的输入通道;用户命令的 stdin 指向 `/dev/null`,stdout/stderr 经管道中继,不会因为持久通道而看到 TTY 并按交互模式运行,读取 stdin 的命令得到 EOF 后结束。程序自身因非 TTY 而缓冲的输出不会被强制改写。`vi`、`top`、需要交互输入的程序和原生作业控制仍应使用 `hdc shell --raw`。
- **历史组织与共享**：当前保留按远端目录分开的历史，所有设备同路径共享。它不同于 OMZ 的全局历史及 `share_history`；增强会话之间不会即时同步历史。

## 验证

自动回归不依赖设备：

```powershell
pwsh -NoProfile -File tests/HdcShell.Tests.ps1
```

本轮在 Linux、PowerShell 7.6.9、PSReadLine 2.4.5 与当前在线设备上验证远端 PATH 发现、路径强调、目录补全、Tab 菜单与 Shift+Tab、与本机 zsh 相同的确认/执行次数、灰色历史与逐词接受、Ctrl+F 行中移动、Ctrl+C 留在设备、Ctrl+D 退出、尾部注释、`cd -`、退出码,以及回到主机后的编辑状态。Windows 未作本轮实机验证。

1.1.3 验证结果：112 项自动检查;35 组相同按键的 111 个缓冲区/光标检查点及提交文本一致;16 组路径强调流程的 22 个终端属性/缓冲区/光标检查点一致;22 项真机检查;450 个候选的 13 项长菜单与缩放检查。安装后的模块再次通过真机及长菜单检查,并验证实际 PowerShell 配置加载 1.1.3、主机提示符不追加设备标签、`hdc shell` 显示 SN 和设备系统版本。

1.1.4 将路径强调从仅下划线改为亮青色加下划线,通过 16 组颜色流程、113 项基础检查和 25 项真机检查,含用户截图中的 `/data/service/el2/100/hmdfs`。1.1.5 默认实时输出通道通过 33 项跨块协议检查、12 项本地持续输出/中断/进程清理/提前输入检查及 10 项真机实时输出检查;原有 113 项基础、25 项真机编辑和 3 组涉及执行的 zsh 按键对照仍通过。真机实时检查使用原样 `hilog`、`dmesg`、日志管道和与 Enter 一起排队的 Ctrl+C,验证中断后的状态 130、无残留测试进程组、主机控制键恢复及 `$Error` 无新增记录。

1.1.6 移除启动时的系统版本读取,将命令扫描与 HOME 查询延迟到需要时,首个提示符前仅发出 `pwd` 查询。提示符为 `SN 末级目录 ->`,箭头成功绿、失败/中断红;暂时关闭 PSReadLine 的 PowerShell 语法错误提示符覆盖,退出时恢复原设置(包括 null)。通过 115 项基础检查、31 项真机编辑/提示符/启动查询检查、5 组路径颜色对照和 4 组逐键对照;安装后的版本再次通过 31 项真机、450 候选的 13 项长菜单以及 10 项日志实时输出检查。

1.1.7 修复只输入 `cat` 等读取 stdin 的命令时整个会话挂起的问题。hdc 始终保持远端 stdin 通道打开,关闭主机侧 stdin 不会在设备端形成 EOF;现在远端脚本先将 stdin 指向 `/dev/null`,`cat`、`sort`、`wc`、`head`、`grep`、`read` 等立即按自身状态返回,命令文本、管道、重定向和文件参数保持原样。同时修正 `ls` 本地排版:选项判断区分大小写(`-S` 不再被当成 `-s`),显式 `-p` 只保留目录标记,非长格式 `-h` 保持设备输出。通过 136 项基础检查、33 项流协议检查、15 项本地实时/中断检查、16 组路径颜色对照、35 组逐键对照,以及新增的真机命令类矩阵 193 项检查;矩阵覆盖平凡、文件读取、stdin、列表、文本搜索、OpenHarmony、复合、状态、Unicode/ANSI、大输出和未知命令,校验执行结果、输入强调色、`ls` 类型与扩展名颜色及各命令延迟(端到端观测,含测试端按键、提示符等待和屏幕解析;最慢约 1 秒)。同机对照中,原生交互 `hdc shell` 的同等命令中位数约 55–152 毫秒,非交互 `hdc -t SN shell CMD` 约 115–165 毫秒,增强会话约 255–400 毫秒;增强开销主要来自每命令独立 hdc 进程/RPC、状态标记与 `pwd` 包装以及本地渲染,stdin 重定向本身未增加可测开销。31 项真机编辑检查和 10 项真机实时输出检查仍通过。

1.1.8 优化交互时延：路径强调不再在每个提示符后强制清空设备目录列表缓存，改为与补全共用的 10 秒 TTL；行内强调结果和控制台样式仍按输入行重置。C# 流循环的等待间隔从 15 ms 降到 2 ms。修正基准测试中 pexpect 默认 50 ms 发送延迟造成的约 100 ms 偏差。连续同目录输入时，路径强调的输入渲染中位数从约 202 ms 降到 65 ms（文件/搜索类从 360–390 ms 降到约 70 ms）；命令执行中位数约 204 ms（非交互 direct 164 ms、原生交互 raw 100 ms）。真机复核通过 138 项基础检查、33 项流协议检查、193 项命令类矩阵、31 项真机编辑、16 组路径颜色、10 项真机实时输出和 35 组逐键对照；详细数据见 [command-performance.md](command-performance.md)。

1.2.0 在 Unix 主机引入持久 `hdc shell` 交互通道：会话启动时通过主机 PTY 建立通道并定义一次远端包装函数,每条命令只发送一条短函数调用,在独立子 shell 中执行；stdin 为 `/dev/null`,stdout/stderr 经管道中继保持非 TTY 语义,状态仍不跨命令保留。交互执行中位数从约 204 ms 降到约 101 ms,简单内建命令约 50 ms；路径强调热缓存渲染仍约 65 ms。Windows、PTY 创建失败或命令行超过 3000 字符时回退到逐命令 RPC。会话启动约 0.65 秒,每次进入只发生一次。真机复核通过 138 项基础检查、33 项流协议检查、193 项命令类矩阵、31 项真机编辑、16 组路径颜色、10 项真机实时输出、15 项本地实时/中断和 35 组逐键对照；详细数据见 [command-performance.md](command-performance.md)。

1.1.1 遗漏了可选择菜单的高度限制,候选列表超过窗口时保存的光标行会滚成负数。1.1.2 将绘制限制在输入行以外的可见区域,以完整候选表维护选择顺序,随当前候选滚动视口;缩放后丢弃旧屏幕坐标并重绘。绘制中途缩放导致的失效帧会重新定位重绘,不向自定义按键处理器或 `$Error` 泄漏坐标异常;菜单清理失败时也会继续恢复主机编辑配置。真机测试使用 450 个候选,覆盖先滚屏、反向选择末项、缩小至 6/4 行再放大、取消与退出恢复;与原有小列表按键对照分开验证。

自定义按键恢复需要保存 PSReadLine 内部的两张按键表,菜单仅复用其内部绘制接口,读取按键和维护输入由模块自己的状态机完成。路径强调通过原生 `IConsole` 代理识别编辑器生成的输入行,只追加 ANSI 样式,光标、换行和按键仍由原编辑器处理;退出时恢复原控制台实例。这些兼容边界集中在编辑状态保存/恢复、`Initialize-HdcShellCompletion` 及路径渲染适配器;遇到不兼容的 PSReadLine 结构会报错,会话清理负责恢复主机配置。
